1 · So funktioniert es

Eine Demo ist der Bauplan für dein Video. Sie enthält Einstellungen und eine geordnete Liste von Szenen. Jede Szene hat eine Startseite, einen gesprochenen Text und Aktionen wie Klicks oder Texteingaben.

  1. Prüfen: Ist der Bauplan vollständig und gültig?
  2. Voiceover erstellen: Den Text sprechen lassen und die Zeitpunkte der Wörter bestimmen.
  3. Aufnehmen: Die App im Browser öffnen und die Aktionen ausführen.
  4. Rendern: Aufnahmen, Stimme und Untertitel zum fertigen MP4 zusammensetzen.

Run full demo führt diese Schritte zusammen aus, einschließlich der Vorbereitung der Anmeldung. Ein Run ist ein einzelner Durchlauf. Eine Demo kann viele Runs haben – etwa einen ersten Versuch und eine verbesserte Version.

Du bearbeitest den Bauplan. Die Factory schneidet daraus automatisch das Video. Änderungen an der Demo ändern eine bereits erzeugte MP4 nicht rückwirkend.

2 · Einmal vorbereiten

Öffne im linken Menü Settings. Hier stehen die Einstellungen für die laufende Factory und die verfügbaren Arbeitsschritte.

Die richtige App erreichen

B1_BASE_URL ist die Adresse der App, die aufgenommen werden soll. Verwende die richtige Umgebung und bei Bedarf die App-Auswahl, zum Beispiel https://meine-umgebung.example/?app=b1-labs. Der Aufnahme-Browser muss diese Adresse erreichen können.

Die Anmeldung vorbereiten

Falls die Ziel-App eine Anmeldung verlangt, braucht auch der Aufnahme-Browser eine gültige Sitzung. Die Factory kann diese mit dem konfigurierten API-Schlüssel vorbereiten. Alternativ kannst du in Settings aus einer Sitzung der Ziel-App einen Auth state erstellen: in der Ziel-App anmelden, den Wert des Cookies b1.session_token aus den Browser-Entwicklertools übernehmen und die dort angebotene Aktion zum Erstellen des Auth state ausführen.

Die Adresse in Settings und die Sitzung müssen zur gleichen Ziel-Umgebung gehören. „Auth state minted“ bedeutet, dass eine Anmeldedatei erstellt wurde. Prüfe trotzdem, ob sie für die tatsächlich aufgenommene Adresse erstellt wurde.

Die Stimme einrichten

Für gesprochene Videos müssen auf dem Server ein ElevenLabs API-Schlüssel und eine Voice-ID verfügbar sein, normalerweise als ELEVENLABS_API_KEY und ELEVENLABS_VOICE_ID. Falls sie fehlen, lass sie von der Person einrichten, die die Umgebung betreibt. Für einen ersten Test kannst du den Provider silent verwenden: Das Video hat dann keine Stimme.

Settings zeigt außerdem, welche Schritte auf diesem Server möglich sind. Wenn Aufnahme oder Rendern nicht verfügbar sind, muss die Umgebung dafür eingerichtet werden.

3 · Mein erstes Video

Starte mit einem kurzen Video: eine App öffnen, eine Funktion zeigen, fertig. Eine oder zwei Szenen reichen für den ersten Versuch.

  1. Eine Demo anlegen

    Öffne Demos und klicke New demo. Wähle eine eindeutige ID wie mein-erstes-video und den Titel „Mein erstes Video“. Die ID darf Kleinbuchstaben, Zahlen und Bindestriche enthalten.

    Unter Start from siehst du, ob eine ausgewählte Demo kopiert wird oder du mit einer leeren Vorlage startest. Eine passende vorhandene Demo ist oft der schnellste Einstieg. Klicke Create demo und öffne die neue Demo über ihren Titel.

  2. Aufnahme-Einstellungen prüfen

    Im Tab Demo prüfst du die Zieladresse. Base URL fallback wird verwendet, wenn die angegebene Umgebungsvariable keinen Wert liefert. Wenn etwa B1_BASE_URL gesetzt ist, hat dieser Wert Vorrang.

    Für den Einstieg sind 1920 × 1080 als Viewport und 30 Frames per second sinnvoll. Der Viewport ist die Größe des aufgenommenen Browserfensters. Klicke Save.

  3. Die erste Szene beschreiben

    Öffne Scenes. Öffne eine vorhandene Szene über ihren Titel oder lege mit Add scene eine an. Gib ihr einen klaren Titel, eine passende Start-Route und einen kurzen Sprechertext. Beispiel: „Hier sehen wir unsere Kunden auf der Karte. Ein Klick auf die Gruppe zeigt die einzelnen Adressen.“

    Eine Route wie /screens/MeineKarte?app=meine-app bezeichnet die Seite innerhalb der Ziel-App. Ersetze sie durch eine wirklich vorhandene Seite. Speichere die Szene über den Save-Button im Szenenfenster.

  4. Die Aktionen ergänzen

    Im Szenenfenster stehen im Tab Actions die auszuführenden Aktionen und die Prüfungen als JSON. Wenn du sie nicht selbst schreiben möchtest, speichere und schließe die Szene, wähle ihre Zeile aus und klicke oben Edit with Demo Agent.

    „Zeige in dieser Szene die Kundenkarte. Klicke auf die Gruppe mit 12 Adressen, damit die Karte hineinzoomt. Stimme den Klick auf den Sprechertext ab.“

    Prüfe den Vorschlag des Agents und die geänderte Demo, bevor du aufnimmst. Weitere Beispiele findest du in Kapitel 5 und 6.

  5. Die Stimme auswählen

    Im Tab Voice-over wählst du elevenlabs für eine Stimme oder silent für einen stummen Test. Setze als Modell zum Beispiel eleven_v4, wenn dein ElevenLabs-Zugang es unterstützt. Für deutschsprachige Texte ist der Language code de. Speichere.

  6. Den Bauplan prüfen

    Klicke im Tab Demo auf Validate. Behebe gemeldete Fehler, etwa eine fehlende Route oder einen falsch geschriebenen Cue. Die Prüfung kontrolliert den Bauplan; ob ein Button in der Ziel-App wirklich vorhanden ist, zeigt erst die Aufnahme.

  7. Das vollständige Video erzeugen

    Klicke oben Run full demo. Die Factory speichert offene Demo-Einstellungen und startet den Durchlauf. In der Statusleiste siehst du den Fortschritt; View log öffnet die Details. Während des Laufs kannst du mit Cancel job abbrechen.

    Die Aufnahme und besonders das Rendern können dauern. Warte auf „Job complete“. Die Factory führt die Aktionen tatsächlich in der Ziel-App aus – verwende dafür passende Demo-Daten.

  8. Das Ergebnis ansehen

    Öffne den Tab Runs, wähle den fertigen Durchlauf und klicke Open video. Prüfe Bild, Stimme, Klicks und Untertitel. Mit Open captions öffnest du die separate Untertiteldatei. Über den Run-Titel kommst du zu den Details und zur Vorschau.

    Wenn du etwas ändern möchtest, passe die Demo an und starte einen neuen vollständigen Durchlauf. Dein erstes Demo-Video ist fertig, sobald die MP4 so aussieht und klingt, wie du es möchtest.

5 · Szenen und Klicks verstehen

Jede Szene startet mit einem frischen Browserzustand. Sie muss ihre Seite selbst öffnen und alles vorbereiten, was sie benötigt. Sie darf sich nicht darauf verlassen, dass eine vorige Szene bereits einen Tab geöffnet hat.

Sprechertext und Cue

Ein Cue ist eine Marke im Sprechertext, zum Beispiel [cue:karte]. Sie wird nicht mitgesprochen. Eine Aktion mit atCue: "karte" wird an diesem Punkt ausgeführt.

„Hier sehen wir die Kundenkarte. [cue:karte] Jetzt öffnen wir die Kartenansicht.“

Eine Aktion als JSON

Actions ist eine Liste in eckigen Klammern. Dieses Beispiel klickt zum Cue auf einen Button mit dem sichtbaren Namen „Karte“. Name und Rolle müssen zur echten App passen.

[
  {
    "action": "click",
    "atCue": "karte",
    "target": { "role": "button", "name": "Karte" }
  }
]

target beschreibt das gesuchte Element. role und name bezeichnen etwa einen Button und seine Beschriftung. text sucht nach sichtbarem Text; css ist ein technischer Selektor. Kartenmarker brauchen häufig einen passenden Selektor – „12“ allein kann mehrere Elemente treffen. Lass den Agent die tatsächliche Oberfläche prüfen.

click klickt, fill setzt einen Feldwert, type tippt ihn, press drückt eine Taste, highlight hebt ein Element hervor. waitFor wartet, bis ein Element sichtbar ist. Lange Wartezeiten lassen sich mit timelapse im fertigen Video verkürzen.

Assertions: Was muss zu sehen sein?

Assertions sind Prüfungen nach den Aktionen. Dieses Beispiel verlangt, dass der Text „Kundenkarte“ sichtbar ist:

[
  { "visible": { "text": "Kundenkarte" } }
]

Ohne Aktionen oder Prüfungen steht im jeweiligen Feld []. Ungültiges JSON wird als Fehler markiert. Korrigiere den Text vor dem Speichern; der ungültige Text ersetzt die strukturierten Daten nicht.

6 · Mit dem Demo-Agent bearbeiten

  1. Öffne die gewünschte Demo.
  2. Wähle unter Scenes die Szene aus, auf die sich dein Wunsch bezieht. Öffne Szenen zum Bearbeiten über ihren Titel; speichere und schließe das Szenenfenster vor dem Chat.
  3. Klicke Edit with Demo Agent in der oberen Toolbar.
  4. Schreibe im Chat, was du ändern möchtest.

Der Chat bekommt die Demo-ID, den Titel und – falls ausgewählt – die Szenen-ID, den Szenentitel und die Position mit. Der Agent soll die aktuelle Definition lesen und zunächst auf deinen Änderungswunsch warten.

„Füge nach dieser Szene eine weitere Szene ein, die zeigt, wie ich einen neuen Kunden anlege. Verwende einen kurzen deutschen Sprechertext.“
„Füge hier noch einen Klick auf den Kartencluster mit 12 Adressen ein, damit die Karte hineinzoomt. Der Klick soll stattfinden, wenn die Stimme ‚einzelne Adressen‘ sagt.“
„Kürze den Sprechertext dieser Szene auf ungefähr 20 Sekunden, aber behalte die Cue-Marken für die Klicks bei.“

Der Kontext wird beim Öffnen des Chats festgelegt. Wenn du später im Studio eine andere Szene auswählst, wechselt ein bereits offener Chat nicht automatisch den Bezug. Nenne dann die neue Szenen-ID oder öffne einen neuen Chat über den Button.

Ohne ausgewählte Szene wird nur die Demo übergeben. Der Agent soll bei „hier“ oder „nach dieser Szene“ nachfragen. Prüfe seine Änderungen anschließend im Studio; lade die Demo bei Bedarf neu. Starte danach eine neue Aufnahme – für den Einstieg am besten wieder mit Run full demo.

7 · Stimme, Untertitel und Timing

Provider bestimmt, ob gesprochen wird: elevenlabs erzeugt Sprache, silent bleibt stumm und auto verwendet ElevenLabs, wenn Schlüssel und Stimme vorhanden sind.

Der Modellname für v4 lautet eleven_v4. eleven_multilingual_v4 ist kein gültiger Modellname. Das bereits verwendete eleven_multilingual_v2 bleibt möglich. Eine serverseitig gesetzte Variable ELEVENLABS_MODEL_ID hat Vorrang vor dem Modellfeld. Stimme und Modell müssen im ElevenLabs-Zugang verfügbar sein.

Längere Texte werden in Stücke aufgeteilt und zusammengefügt. Gleichbleibende Texte und Stimmeinstellungen können aus dem Cache wiederverwendet werden. Das spart erneute Sprachgenerierung.

Ändert sich der Sprechertext oder die Stimme, können sich die Zeitpunkte der Aktionen ändern. Erzeuge das Voiceover neu, nimm danach die Szenen auf und rendere anschließend – oder starte den vollständigen Durchlauf.

Show the cursor overlay blendet den Demo-Mauszeiger ein. Burn captions into the video macht Untertitel direkt im Bild sichtbar. Zusätzlich entsteht eine separate SRT-Datei.

30 fps bedeutet 30 Bilder pro Sekunde und ist ein guter Standard für App-Demos. 60 fps erzeugt mehr Bilder und erhöht den Renderaufwand. Für Tabellen, Formulare und normale Klickabläufe genügt meist 30 fps.

8 · Ergebnisse und Ablage

Der Bauplan lässt sich über Demo → More actions → Export als demo.yaml sichern und später importieren. Diese Datei beschreibt das Video; sie ist selbst kein Video.

Jeder Durchlauf hat einen eigenen Ordner mit einer Run-ID. Nach dem Rendern findest du dort die MP4, die SRT-Untertitel und Angaben zum Durchlauf. Öffne das Ergebnis am einfachsten über den ausgewählten Run in der App.

Den Ausgabeordner bestimmt DEMO_OUTPUT_DIR, den Sprach-Cache DEMO_CACHE_DIR. Ohne Konfiguration liegt die Ausgabe im output-Ordner der Factory. Deshalb kann im Workspace ein Pfad unter /workspace/src/app-server-ts/demo-factory/output erscheinen.

Die Standalone-Deployment-Konfiguration dieses Projekts verwendet /data/demo-factory/output und /data/demo-factory/cache auf einem dauerhaften Volume. Falls du eine andere Ablage möchtest, ändere die Laufzeitkonfiguration über Settings beziehungsweise die Server-Umgebung. Vorhandene Ergebnisse werden dadurch nicht automatisch verschoben.

9 · Wenn etwas nicht klappt

Das Log zeigt die Anmeldeseite

Prüfe die Zieladresse und den Auth state. Eine Sitzung für eine andere Domain hilft nicht. Melde dich in der Ziel-App an und erstelle einen neuen Auth state für genau diese Umgebung. Ein Fehler beim API-Schlüssel kann dazu führen, dass die Factory einen alten gespeicherten Zustand verwendet.

„Model not found“ bei ElevenLabs

Prüfe den Modellnamen. Für v4 verwende eleven_v4. Prüfe auch, ob eine Server-Variable das Feld überschreibt und ob dein Zugang das Modell unterstützt.

Ein Klick läuft in einen Timeout

Die Factory findet das gesuchte Element nicht rechtzeitig. Öffne die Zielseite selbst: Ist die richtige App geladen? Bist du angemeldet? Stimmt der Text des Buttons? Muss vorher ein anderer Tab geöffnet oder auf Daten gewartet werden? Das Log nennt das gesuchte Element; bei fehlgeschlagenen Aufnahmen wird auch ein Screenshot-Pfad ausgegeben.

Kein formatiertes JSON oder Speichern klappt nicht

Actions und Assertions müssen Listen sein, zum Beispiel [] oder die Beispiele in Kapitel 5. Prüfe Anführungszeichen, Kommas und Klammern. Auch fehlende Titel, ungültige Routen oder ein unbekannter Cue können das Speichern verhindern.

Kein fertiges Video trotz Voiceover

Voiceover ist nur der erste Produktionsschritt. Danach brauchst du Aufnahme und Rendern. Wähle einen erfolgreich aufgenommenen Run zum Rendern oder starte Run full demo.

Das Rendern dauert lange oder bricht ab

Rendern ist der aufwendigste Schritt. Öffne View log, um den Fortschritt und den Fehler zu sehen. Bei einem Speicher- oder Browserfehler muss die Server-Konfiguration geprüft werden. Für eine gezielte Meldung notiere Demo-ID, Run-ID und die letzte Fehlermeldung.

Diese Anleitung gehört zur B1 Demo Factory. Die Button-Namen entsprechen der englischen App-Oberfläche.
